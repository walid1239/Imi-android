# رسالة تنفيذ المعاينة إلى مالك IMI

هذه الرسالة دليل تنفيذ من البداية إلى اختبار معاينة الويب. اتبع الترتيب ولا تتجاوز خطوة فاشلة. لا أستطيع اعتبار المعاينة ناجحة قبل أن تنفذها أنت وتراجع النتائج.

## 1. ما الذي سنفعله والحدود والوقت

سنجهّز مشروع Firebase الحالي `imi-indroid` على خطة Spark المجانية، ونربطه بمشروع Vercel مجاني لإنتاج رابط **Preview** فقط، ثم نختبر الدخول والأكاديمية وبعض وظائف التطبيق. بعد ذلك، إذا وافقت صراحة وبعد نجاح الفحوص، يمكنك نشر قواعد Firestore وفهارسه وبناء نسخة Android تجريبية.

- التقدير العملي: نحو 45–90 دقيقة إذا كانت الحسابات جاهزة، وقد يزيد إذا طلبت Google أو Firebase تحققاً إضافياً.
- لا تحتاج إلى بطاقة بنكية، ولا إلى Blaze، ولا إلى خدمة مدفوعة. Firebase Spark وVercel Hobby متاحان دون دفع ضمن حدود وشروط الاستخدام.
- **تنبيه Vercel:** خطة Hobby مخصصة للاستخدام الشخصي وغير التجاري. إذا كان استخدام IMI تجارياً أو موجهاً لتحقيق دخل، فتوقف ولا تستخدم Hobby لهذا الغرض قبل إيجاد مضيف مجاني يسمح صراحة بالاستخدام التجاري.
- ممنوع تفعيل Blaze أو ربط بطاقة أو شراء خطة.
- ممنوع اختيار Production أو إنشاء نشر إنتاجي.
- ممنوع دمج PR #5 أو PR #2. سنستخدم فرع العمل للمعاينة فقط، وسيبقى PR #5 مفتوحاً وDraft.
- ممنوع نشر Cloud Functions أو قواعد Storage أو تشغيل أي خدمة مدفوعة.
- لا ترسل أي مفتاح خاص أو رمز دخول إلى أي شخص أو محادثة.

المستودع: `walid1239/Imi-android`. فرع المعاينة المقصود: `work/imi-web-foundation-audit-fixes`. هذا الفرع يحتوي تغييرات PR #5 الحالية؛ أما `feature/imi-web-foundation` فهو الفرع الأساسي ولا يحتوي هذه التغييرات قبل دمجها.

## 2. تفعيل طرق الدخول في Firebase

1. افتح [Firebase Console](https://console.firebase.google.com/).
2. اختر المشروع `imi-indroid` وتأكد من ظهور اسمه أعلى الصفحة.
3. من القائمة افتح **Build → Authentication**.
4. اضغط **Get started** إذا ظهرت لك.
5. افتح تبويب **Sign-in method**.
6. افتح **Anonymous** ثم فعّل **Enable** واحفظ. هذا يسمح بالدخول كضيف.
7. افتح **Email/Password** ثم فعّل خيار البريد وكلمة المرور واحفظ.
8. افتح **Google** ثم فعّل **Enable**. إذا طلب بريد دعم المشروع، أدخل بريدك المناسب واحفظ.
9. لا تفعّل Phone أو OTP؛ تسجيل الهاتف وWhatsApp غير معتمدين في هذه النسخة.

**كيف تعرف أنها فُعّلت؟** ارجع إلى قائمة **Sign-in method** وتأكد أن Anonymous وEmail/Password وGoogle تظهر بحالة Enabled. لا تنتقل قبل ذلك.

## 3. نسخ إعدادات تطبيق الويب إلى متغيرات Vercel

1. في Firebase Console افتح ترس **Project settings**.
2. انزل إلى **Your apps** واختر تطبيق الويب الخاص بـ IMI. إذا لم يكن هناك تطبيق ويب، لا تنشئ تطبيقاً باسم عشوائي؛ أنشئ تطبيق Web باسم IMI ثم افتح إعداداته.
3. اختر إعدادات SDK الخاصة بتطبيق الويب واعرض قيم الإعدادات.
4. في Vercel ستضيف القيم التالية حرفياً. انسخ قيمة كل حقل من إعداد تطبيق الويب المطابق للمشروع `imi-indroid`:

```text
NEXT_PUBLIC_FIREBASE_API_KEY
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN
NEXT_PUBLIC_FIREBASE_PROJECT_ID
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID
NEXT_PUBLIC_FIREBASE_APP_ID
FIREBASE_PROJECT_ID
```

اجعل قيمة `FIREBASE_PROJECT_ID` هي `imi-indroid` حرفياً. لا تضع أي قيمة تخمينية. المتغيرات الستة الأولى هي إعدادات تطبيق الويب العامة، وليست مفتاح حساب الخدمة.

لا تضف متغيرات المحاكيات التالية إلى إعداد Preview، واتركها غير موجودة:

```text
NEXT_PUBLIC_FIREBASE_EMULATORS
IMI_USE_FIREBASE_EMULATORS
FIREBASE_AUTH_EMULATOR_HOST
FIRESTORE_EMULATOR_HOST
FIREBASE_STORAGE_EMULATOR_HOST
FIREBASE_DATABASE_EMULATOR_HOST
```

## 4. إنشاء مفتاح حساب الخدمة وإضافته إلى Vercel فقط

يحتاج خادم Next.js إلى حساب خدمة لاستخدام Firebase Admin SDK. المفتاح ملف سري للغاية.

1. افتح [Google Cloud Console](https://console.cloud.google.com/).
2. اختر المشروع `imi-indroid` من شريط المشاريع.
3. افتح **IAM & Admin → Service Accounts**.
4. اختر حساب خدمة تابعاً لهذا المشروع ومصرحاً له بالعمليات التي يحتاجها خادم IMI على Firebase Authentication وFirestore.
5. افتح تبويب **Keys** ثم **Add key → Create new key → JSON**.
6. نزّل الملف إلى جهازك. لا تضعه داخل مجلد المستودع ولا داخل مجلد المشروع.
7. افتح الملف محلياً بمحرر نصوص، وانسخ محتواه كاملاً. لا ترسل الملف أو محتواه إلى ChatGPT أو Claude أو أي شخص.
8. في Vercel، افتح مشروع IMI ثم **Settings → Environment Variables**.
9. أضف متغيراً اسمه حرفياً `FIREBASE_SERVICE_ACCOUNT_JSON`، والصق محتوى JSON كاملاً في خانة القيمة. اجعل البيئة **Preview** فقط، ثم احفظ.
10. يجب أن يكون JSON صالحاً وفيه `project_id` يساوي `imi-indroid`. لا تضف بادئة `NEXT_PUBLIC_` لهذا المتغير.
11. بعد التأكد أن القيمة حُفظت في إعداد Preview، احذف ملف JSON المحلي من جهازك. لا تحتفظ بنسخة منه في Downloads أو المستودع أو النسخ الاحتياطية غير المحمية.

إذا لم تعرف أي حساب خدمة يملك الصلاحيات الصحيحة، توقف ولا تنشئ حساباً أو تمنحه أدواراً عشوائية. اطلب من مسؤول المشروع تحديد حساب الخدمة والصلاحيات المطلوبة. إنشاء مفتاح لا يكلّف مالاً بحد ذاته، لكن حمايته مسؤوليتك.

## 5. إنشاء مشروع Vercel وضبطه للمعاينة فقط

1. افتح [Vercel](https://vercel.com/) وسجّل الدخول.
2. اضغط **Add New → Project**.
3. اربط حساب GitHub إذا طُلب، ثم اختر المستودع `walid1239/Imi-android`.
4. في إعدادات المشروع اضبط **Root Directory** على `web`.
5. افتح إعداد Root Directory وفعّل **Include source files outside of the Root Directory** أو الخيار المكافئ الذي يسمح بإدخال الملفات المشتركة خارج `web`. يحتاج التطبيق إلى ملفات من `functions/src/shared`.
6. اختر فرع المعاينة `work/imi-web-foundation-audit-fixes`. لا تختَر `feature/imi-web-foundation` إذا كنت تريد الكود الموجود في PR #5.
7. في إعدادات المتغيرات، اجعل كل المتغيرات التي أضفتها في القسمين 3 و4 متاحة لبيئة **Preview** فقط. لا تضفها إلى Production.
8. اترك أمر البناء ومجلد الإخراج الافتراضيين كما هما. إعداد `web/next.config.ts` يتولى جذر تتبع الملفات.
9. لا تغيّر أي إعداد فوترة ولا تضف بطاقة.
10. بعد إكمال الإعدادات، أنشئ نشر **Preview** فقط من الفرع المحدد. لا تضغط Deploy Production ولا تستخدم نطاق Production.

قد يحتاج أول بناء إلى عدة دقائق. إذا فشل، لا تكرر النشر دون قراءة أول خطأ في سجل البناء.

## 6. إضافة نطاق المعاينة إلى Firebase

بعد نجاح أول نشر Preview:

1. انسخ اسم النطاق الذي أعطاه Vercel، مثل `imi-example.vercel.app`.
2. ارجع إلى Firebase Console واختر `imi-indroid`.
3. افتح **Authentication → Settings → Authorized domains**.
4. اضغط **Add domain**.
5. الصق اسم النطاق فقط، دون `https://` ودون أي مسار، ثم احفظ.
6. أعد فتح رابط المعاينة.

هذا الإعداد مطلوب لتسجيل الدخول من نطاق Vercel. لا تضف نطاقاً لا تملكه أو لا تستخدمه.

## 7. منح حساب المالك صلاحية المشرف

هذه الخطوة تمنح صلاحية فعلية في Firebase Authentication. نفّذها لحساب المالك وحده، بعد أول دخول ناجح إلى IMI.

### أ. انسخ UID من Firebase

1. سجّل الدخول مرة واحدة إلى رابط المعاينة باستخدام حساب المالك.
2. افتح Firebase Console → المشروع `imi-indroid` → **Authentication → Users**.
3. ابحث عن حساب المالك الذي أنشأته للتو.
4. انسخ قيمة **User UID**. لا تنسخ البريد؛ السكربت يحدد الحساب بالـ UID حصراً.

### ب. جهّز الاعتماد على جهازك

السكربت `functions/scripts/grant-admin.cjs` يستخدم Application Default Credentials. اختر إحدى الطريقتين:

**الطريقة الأسهل دون ملف مفتاح:** ثبّت Google Cloud CLI ثم نفّذ:

```bash
gcloud auth application-default login
```

سجّل الدخول بحساب Google الذي يملك صلاحية إدارة Firebase Authentication في المشروع. تسجيل الدخول وحده لا يمنح صلاحية IAM؛ يجب أن يكون الحساب مخولاً فعلاً.

**أو باستخدام ملف حساب خدمة:** من Google Cloud Console افتح **IAM & Admin → Service Accounts**، واختر حساب الخدمة المصرح له في المشروع، ثم **Keys → Add key → Create new key → JSON**. احفظ الملف خارج المستودع.

Windows PowerShell:

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\Users\YOUR_USER\PrivateKeys\imi-indroid-admin.json"
```

macOS أو Linux:

```bash
export GOOGLE_APPLICATION_CREDENTIALS="$HOME/PrivateKeys/imi-indroid-admin.json"
```

### ج. شغّل السكربت من جذر المستودع

ثبّت الاعتماديات المحلية أولاً:

```bash
npm ci --prefix functions
```

ثم استبدل `PASTE_UID_HERE` بالـ UID الذي نسخته.

Windows PowerShell:

```powershell
$env:GCLOUD_PROJECT = "imi-indroid"
$env:IMI_ADMIN_UID = "PASTE_UID_HERE"
$env:CONFIRM_GRANT_IMI_ADMIN = "GRANT_ADMIN_TO_PASTE_UID_HERE"
node functions/scripts/grant-admin.cjs
```

macOS أو Linux:

```bash
export GCLOUD_PROJECT="imi-indroid"
export IMI_ADMIN_UID="PASTE_UID_HERE"
export CONFIRM_GRANT_IMI_ADMIN="GRANT_ADMIN_TO_PASTE_UID_HERE"
node functions/scripts/grant-admin.cjs
```

تأكد أن النص بعد `GRANT_ADMIN_TO_` يساوي UID نفسه حرفياً. السكربت يضيف `admin: true` إلى المطالبات المخصصة الموجودة، ثم يعيد قراءة الحساب للتحقق. لا يمنح الصلاحية بالبريد ولا ينشئ حساباً.

عند النجاح ستظهر رسالة شبيهة بهذه:

```text
Granted and verified IMI admin claim for UID PASTE_UID_HERE in project imi-indroid. The user must refresh their ID token.
```

إذا ظهر `Set IMI_ADMIN_UID and GCLOUD_PROJECT` فهناك متغير ناقص. إذا ظهر `Refusing to grant admin outside the approved IMI project` فراجع معرّف المشروع. إذا ظهر `Set CONFIRM_GRANT_IMI_ADMIN` فأصلح نص التأكيد. إذا ظهر `auth/user-not-found` فراجع UID في Authentication → Users. إذا ظهر خطأ اعتماد أو Permission denied، أعد تسجيل الدخول أو اطلب صلاحية IAM الصحيحة؛ لا تحاول تجاوز الخطأ.

بعد النجاح سجّل الخروج من IMI ثم ادخل مجدداً بالحساب نفسه لتجديد رمز الدخول. افتح `/app`: يجب أن يظهر تبويب **إدارة الأكاديمية**. جرّب بحساب عادي آخر: يجب ألا يظهر التبويب، وعند فتح لوحة الإدارة مباشرة يجب أن تظهر رسالة أن الصفحة للمشرفين فقط.

**تحذير:** لا ترفع مفتاح حساب الخدمة إلى Git، ولا ترسله إلى أحد، ولا تلصقه في هذه المحادثة. بعد تشغيل السكربت احذف ملف JSON المحلي. إذا استخدمت Google ADC دون ملف مفتاح فلا يوجد ملف JSON لهذا الإجراء لتحذفه.

## 8. استيراد هيكل الأكاديمية ومعاينة نشره

هذه الخطوة تكتب في Firestore الحقيقي للمشروع `imi-indroid`، حتى لو كانت العناصر المستوردة مخفية. نفذها فقط إذا كنت توافق على إضافة هذا الهيكل إلى قاعدة بيانات المشروع.

1. افتح IMI بحساب المشرف، ثم **إدارة الأكاديمية → إدارة شجرة المنهاج**.
2. اضغط **استيراد JSON** واختر الملف `data/curriculum.json` من نسخة المستودع التي نزّلتها.
3. يعرض التطبيق رسالة بعد الاستيراد بعدد العقد التي أضيفت. إذا رفض الاستيراد لأن معرفاً موجوداً، لا تحذف بيانات موجودة؛ توقف وراجع التعارض.
4. ملف `data/curriculum.json` الحالي يصف هيكلاً أولياً بلا دروس، وينص على أن البيانات ليست مصفوفة وزارية مصادقاً عليها. لا تقدمه كمنهاج رسمي نهائي.
5. لكل عقدة من نوع مستوى، اضغط **معاينة النشر** وسجّل العدد والأنواع التي تظهر. المعاينة تستخدم `dryRun: true` ولا تعدل البيانات.
6. راجع كل مستوى ومصدره وترتيبه وعلاقاته الأبوية. إذا كانت البيانات غير صحيحة، لا تنشرها.
7. بعد موافقتك الصريحة على نشر الهيكل، اضغط **نشر الهيكل** لكل مستوى تريد نشره. هذا الإجراء يكتب في Firestore ويجعل العقد التابعة للمستوى منشورة.
8. العناصر المستوردة تبدأ مخفية وبحالة `needsReview: true`. لا تستخدم زر **اعتماد ونشر** الفردي؛ هذه المراجعة متوقفة مؤقتاً. لا تنشئ دروساً أو دورات تجريبية بغرض إظهار محتوى غير موجود.

## 9. فحوص القبول بالنقر

استخدم حسابين تجريبيين على الأقل، ولا تستخدم بيانات أشخاص حقيقيين. هذه فحوص يدوية وليست ضماناً مسبقاً بأن كل خدمة ستنجح:

1. افتح `/login` وأنشئ حساب اختبار بالبريد وكلمة المرور، ثم سجّل الخروج والدخول.
2. سجّل الخروج، ثم جرّب **المتابعة باستخدام Google**.
3. سجّل الخروج، ثم جرّب **الدخول السريع كضيف**.
4. من حساب اختبار افتح تبويب **الحالات** وأنشئ حالة اختبار نصية إن كانت عناصر الإنشاء متاحة؛ حدّث الصفحة وتحقق من ظهورها. لا ترفع صوراً أو فيديوهات في هذا الاختبار.
5. افتح تبويب **الأصدقاء** وأرسل/اقبل طلب صداقة بين حسابي الاختبار إذا كانت عناصر الطلب متاحة، ثم افتح تبويب **المحادثات** وحاول فتح محادثة بين الحسابين وإرسال رسالة اختبار.
6. افتح **الأكاديمية** وتصفح المستويات والعقد التي وافقت على نشرها. تذكّر أن ملف المنهاج الحالي لا يحتوي دروساً.
7. افتح `/teacher/apply` بحساب اختبار مسجل الدخول. أدخل الاسم الكامل ورابط إثبات يبدأ بـ `https://` واختر مستوى منشوراً ومادة منشورة ثم أرسل الطلب.
8. افتح **إدارة الأكاديمية** بحساب المشرف، وابحث عن الطلب، ثم اعتمده. تحقق من ظهور رسالة نجاح.
9. جرّب بحساب عادي أن تبويب **إدارة الأكاديمية** غير ظاهر.

إذا فشل أي اختبار، سجّل نص الخطأ والخطوة التي حدثت فيها. لا تعتبر فشل الحالات أو المحادثات أو الأصدقاء مقبولاً لمجرد أن صفحة الدخول فتحت.

**حدود معروفة في الكود الحالي:** بعض إجراءات إدارة الدورات والدروس ومراجعة محتوى الأساتذة القديمة متوقفة عمداً وتعرض رسالة تفيد بأنها لم ترسل إلى Cloud Functions. لا تعتبر إنشاء دورة أو درس أو مراجعة محتوى أستاذ اختبار قبول ناجحاً في هذه المرحلة. كذلك لم يثبت اختبار جهاز Android فعلي أو مكالمة فيديو حقيقية.

## 10. نشر قواعد Firestore والفهارس — بموافقة منفصلة فقط

لا تنفذ هذا القسم تلقائياً. أولاً تحقق من أن أحدث CI على فرع المعاينة أخضر، ثم راجع تغييرات `firestore.rules` و`firestore.indexes.json` ووافق صراحة على نشرها إلى مشروع `imi-indroid`.

من جذر المستودع نفّذ الأوامر التالية بعد موافقتك:

```bash
npx --yes firebase-tools@15.37.0 login
npx --yes firebase-tools@15.37.0 use imi-indroid
npx --yes firebase-tools@15.37.0 deploy --only firestore:rules,firestore:indexes
```

هذا الأمر ينشر قواعد Firestore وفهارسه فقط حسب المسارات الموجودة في `firebase.json`. لا تضف `storage` أو `functions` أو `hosting`. لا تنشر Cloud Functions إطلاقاً ضمن هذه الخطة.

## 11. بناء نسخة Android التجريبية

ملف إعداد التطبيق هو `app/build.gradle.kts` في جذر المستودع. البناء يستخدم JDK 17 وAndroid SDK 35 وGradle 8.9. لا يوجد ملف Gradle Wrapper `gradlew` متحقق منه في هذا الفرع؛ لذلك يجب أن يكون Gradle 8.9 مثبتاً محلياً.

1. ضع `google-services.json` محلياً في `app/google-services.json` إذا كنت تريد تهيئة Firebase Android. الملف مستثنى من Git؛ لا ترفعه ولا ترسله إلى المحادثة.
2. افتح الطرفية في جذر المستودع.
3. نفّذ:

```bash
gradle --no-daemon assembleDebug -PIMI_API_BASE_URL=https://<preview-domain>
```

استبدل `<preview-domain>` بنطاق Vercel الفعلي من دون أقواس. الناتج المتوقع هو:

```text
app/build/outputs/apk/debug/app-debug.apk
```

هذه نسخة Debug للاختبار فقط وليست نسخة Release موقعة ولا موافقة للنشر. يمكن أيضاً تنزيل عنصر CI المسمى `IMI-debug-apk-firebase-configured` من تبويب Actions في GitHub إذا كان ما زال ضمن مدة الاحتفاظ. لا يعني نجاح البناء أن التطبيق اختُبر على هاتف فعلي.

## 12. أخطاء شائعة وكيفية التعامل معها

| الخطأ أو الحالة | ما تفعله |
|---|---|
| `CONFIGURATION_NOT_FOUND` أو `auth/configuration-not-found` | راجع القيم العامة الستة في Vercel، وتأكد أن `NEXT_PUBLIC_FIREBASE_PROJECT_ID` هو `imi-indroid`، وأن طريقة الدخول مفعّلة في Authentication → Sign-in method. |
| `auth/unauthorized-domain` | أضف نطاق Vercel الفعلي، دون `https://` أو مسار، إلى Authentication → Settings → Authorized domains. |
| فشل بناء Vercel بسبب ملف من خارج `web` أو من `functions/src/shared` | راجع Root Directory = `web`، وفعّل تضمين الملفات خارج مجلد الجذر، ولا تغير `web/next.config.ts` أو جذر تتبع الملفات. |
| HTTP 401 | سجّل الخروج والدخول مجدداً لتجديد Firebase ID token، وتأكد أنك تستخدم حساباً صالحاً. |
| HTTP 403 | العملية غير مسموح بها للحساب أو لا يملك مطالبة المشرف المطلوبة. لا تمنح `admin: true` لمجرد تجاوز الرفض. |
| HTTP 429 | تم تجاوز حد الطلبات. توقف عن إعادة المحاولة وانتظر انتهاء نافذة الحد. |
| صفحة فارغة أو خطأ CSP | افتح أدوات المطور في المتصفح ثم Console وNetwork. انسخ رسالة Content-Security-Policy وعنوان المورد المحظور. لا تعطل سياسة الحماية عشوائياً ولا تحذفها قبل معرفة المورد والسبب. |
| فشل Firebase Admin | تحقق من JSON في Vercel دون نسخه إلى أي محادثة، ومن أن `project_id` و`FIREBASE_PROJECT_ID` يساويان `imi-indroid`. |
| فشل الأكاديمية في قراءة البيانات | تحقق أن العقد منشورة و`needsReview=false` وأن قواعد Firestore الحالية تسمح بالقراءة. لا تنشر قواعد جديدة إلا حسب القسم 10. |

## 13. ماذا ترسل عند ظهور خطأ؟

أرسل إلى ChatGPT وإلى Claude:

1. اسم الخطوة ورقمها.
2. نص رسالة الخطأ كاملاً كما ظهر، أو لقطة شاشة توضح الصفحة والخطأ.
3. رابط صفحة المعاينة إذا لم يتضمن معلومات خاصة.
4. وقت حدوث الخطأ، والمتصفح أو الهاتف المستخدم.
5. إذا كان الخطأ في Vercel، أرسل اسم مرحلة البناء وأول رسالة خطأ حقيقية من السجل، بعد إخفاء القيم الخاصة.

**لا ترسل أبداً:** مفتاح حساب الخدمة أو ملف JSON، أو قيمة `private_key`، أو `FIREBASE_SERVICE_ACCOUNT_JSON`، أو Firebase ID token، أو Access token، أو كلمة مرور، أو ملف `google-services.json`، أو أي ملف اعتماد. لا تلصق الأسرار في الدردشة حتى لو طلب منك أحد ذلك. إذا ظهر سر في لقطة شاشة فاحجبه قبل الإرسال.
